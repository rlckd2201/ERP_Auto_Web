# ERP 회계업무 자동화 개발 견적 요청서(RFP) 초안

> **문서 상태: Target-state RFP (향후 전환 목표)**
>
> 이 문서는 현재 운영 중인 GUI 자동화 구조를 설명하거나 그 변경을 지시하는
> 문서가 아닙니다. 현행 시스템은 운영서버와 담당자 PC Agent가 K-System GUI,
> Excel, 프린터 작업을 분담하는 방식입니다. 본 RFP는 이를 장기적으로 ERP의
> 공식 API·DB·배치 인터페이스 기반 연계로 전환할 수 있는지 견적받기 위한
> 목표 상태 문서이며, GUI 자동화의 삭제·축소 범위를 확정하지 않습니다.

- 문서 버전: v0.1
- 작성일: 2026-07-08
- 대상: ERP 개발/유지보수 업체
- 목적: 당사가 도입을 검토 중인 회계업무 자동화 기능을 ERP 정식 연계 방식으로 개발할 경우의 개발 범위, 일정, 비용 견적 산출

## 1. 요청 배경

당사는 구매 및 정기 비용 세금계산서 처리 업무의 자동화를 검토하고 있습니다. 도입하고자 하는 시스템은 메일 수신, 세금계산서 PDF 저장, 구매 견적서/품의서 매칭, 전표 데이터 생성, 현금출금결의서 생성, 문서 세트 출력, 정기 세금계산서 누락 모니터링 등을 포함합니다.

본 RFP는 당사가 계획 중인 회계업무 자동화 기능을 ERP 업체가 정식 ERP 연계 방식으로 개발할 경우의 견적을 받기 위한 문서입니다. 실제 개발 진행 여부는 별도 검토 예정이며, 우선 기능별 견적과 구현 가능성을 확인하고자 합니다.

## 2. 견적 산출 전제

ERP 업체는 ERP 데이터베이스, 공식 API, 배치 인터페이스 또는 ERP에서 제공하는 표준 연계 방식을 이용해 구현하는 것을 전제로 합니다.

다음 방식은 본 견적 범위의 필수 구현 방식으로 보지 않습니다.

- 사용자의 화면 조작을 모방하는 방식
- ERP 클라이언트 화면 조작 순서에 의존하는 방식
- 브라우저/ERP 클라이언트 UI 자동화에 의존하는 방식

ERP 업체는 가능한 경우 ERP 내부 데이터 구조 또는 공식 인터페이스를 통해 전표, 첨부문서, 사업장, 거래처, 계정과목, 품목, 부서, 출력물 정보를 직접 등록/조회/수정하는 방안을 제안해 주시기 바랍니다.

## 3. 도입 검토 범위 요약

도입을 검토 중인 시스템은 크게 다음 업무를 처리하는 것을 목표로 합니다.

1. 구매 세금계산서 처리
2. 정기 세금계산서 처리
3. Zoom 청구서 처리
4. 현금출금결의서 생성
5. ERP 전표 등록 및 전표 PDF 보관
6. 문서 세트 저장/통합/출력
7. 정기 세금계산서 누락 모니터링 및 거래처 안내 메일 발송
8. 처리 상태, 작업 로그, 오류 이력, 수동 보정 화면 제공

## 4. 업무 대상

### 4.1 구매 처리

구매 처리 대상은 주로 컴퓨존 등 구매처에서 수신되는 세금계산서 및 관련 견적서/품의서입니다.

주요 업무 흐름은 다음과 같습니다.

1. 구매 세금계산서 메일 수신
2. 세금계산서 PDF/XML 또는 관련 첨부 저장
3. 거래처, 사업장, 작성일자, 공급가액, 부가세, 합계금액 추출
4. 구매 견적서 자동 매칭 또는 수동 첨부
5. 세금계산서와 견적서를 분석하여 구매 품목 목록 생성
6. 품목별 계정과목, 수량, 금액, 부서, 원문 설명 저장
7. 담당자가 화면에서 분석 결과를 수정하고 저장
8. 수정된 결과를 다음 분석 및 전표 생성에 반영
9. ERP 전표 데이터 생성
10. 전표 PDF, 세금계산서, 품의결재본, 현금출금결의서를 문서 세트로 관리
11. 통합 PDF 저장 또는 프린터 출력

### 4.2 정기 처리

정기 처리 대상은 매월 또는 분기별로 반복 수신되는 고정 거래처 세금계산서입니다.

관리 대상 주요 거래처 예시는 다음과 같습니다.

- KT
- 현대오토에버
- 다우기술
- 시큐어포인트
- 동양정보통신
- 대신아이씨티
- 이테크시스템
- 에티버스
- 안랩
- 피플러스/GRADIUS
- Zoom

주요 업무 흐름은 다음과 같습니다.

1. 정기 세금계산서 메일 수신
2. 거래처별 수신 예정일, 작성 기준일, 주기 확인
3. 세금계산서 PDF/XML 저장
4. 중복 수신 방지
5. ERP 전표 등록 대상 생성
6. ERP 전표 생성 및 전표 PDF 보관
7. 현금출금결의서 생성
8. 지정 프린터로 자동 출력 또는 수동 재출력
9. 수신 누락 시 내부 담당자 및 거래처 안내 메일 발송

### 4.3 Zoom 청구서 처리

Zoom은 일반 세금계산서/전표 처리와 다르게 처리합니다.

요구 사항은 다음과 같습니다.

- Zoom 청구서 메일에서 PDF 청구서를 저장합니다.
- Zoom은 ERP 전표와 품의결재본을 생성하지 않습니다.
- 출력 문서는 청구서와 현금출금결의서만 필요합니다.
- 금액은 환율 계산을 하지 않고 PDF 또는 DB에 저장된 표시 금액 그대로 사용합니다.
- USD로 표시된 경우도 원화 환산 없이 표시 금액 그대로 현금출금결의서에 기재합니다.
- 청구서와 현금출금결의서가 준비되면 지정 프린터로 출력합니다.
- 사용자가 수동으로 원클릭 처리 또는 재출력을 수행할 수 있어야 합니다.

## 5. 상세 요구사항

### 5.1 메일 수신 및 세금계산서 수집

ERP 또는 연계 시스템은 세금계산서 관련 메일을 자동으로 수집해야 합니다.

필수 기능은 다음과 같습니다.

- 메일 계정 연동
- 읽지 않은 메일 및 최근 수신 메일 재확인
- 이미 읽은 메일도 일정 기간 내 재수집 가능
- 수신 이력 저장
- 중복 처리 방지
- 세금계산서 후보 판정
- 업무 대상 외 메일 제외
- 수집 실패 이력 저장
- 메일 제목, 발신자, 수신일, 메시지 ID 저장
- 세금계산서 링크 또는 첨부파일에서 PDF/XML 확보
- PDF 파일명 안전 처리 및 서버 보관

메일 수집 결과는 다음 상태로 구분되어야 합니다.

- 신규 저장
- 중복
- 업무 대상 외 제외
- 지원 불가
- 다운로드 실패
- 분석 실패
- 수동 확인 필요

### 5.2 세금계산서 데이터 추출

세금계산서 PDF/XML에서 다음 데이터를 추출해야 합니다.

- 공급자 상호
- 공급자 사업자등록번호
- 공급받는자 상호
- 공급받는자 사업자등록번호
- 작성일자
- 공급가액
- 부가세
- 합계금액
- 품목명
- 품목 금액
- 메일 제목
- 원본 PDF 경로
- XML 원본 데이터

사업장은 법인명만으로 판단하지 않고 공급받는자 사업자등록번호 또는 ERP 사업장 매핑 기준으로 결정해야 합니다.

예: `(주)대승`이 아니라 `D1공장`, `P1공장`, `P3공장`, `P4공장`, `일강1공장`, `일강2공장` 등 실제 ERP 사업장명으로 저장 및 전표 작성

### 5.3 구매 견적서 및 품의결재본 연계

구매 처리 건은 세금계산서 외에 견적서와 품의결재본이 필요합니다.

필수 기능은 다음과 같습니다.

- 구매처별 주문번호 추출
- 주문번호 또는 금액 기준 견적서 자동 매칭
- 견적서 PDF 자동 보관
- 품의결재본 PDF 자동 매칭 또는 수동 첨부
- 첨부 문서 교체/추가
- 문서 누락 상태 표시
- 품의결재본 다운로드 실패 시 오류 사유 기록

컴퓨존의 경우 자동화 대상 구매처로 검토 중이며, 주문번호 기준 견적서 확보 및 품목 분석이 필요합니다.

### 5.4 구매 품목 분석 및 계정과목 분류

세금계산서와 견적서를 함께 분석하여 ERP 전표 입력용 품목 데이터를 생성해야 합니다.

필수 기능은 다음과 같습니다.

- 견적서 품목 행 추출
- 같은 품목/단가의 중복 행 병합
- 품목명 ERP 입력용 정리
- 수량, 공급가액, 부가세, 합계금액 정합성 검증
- 계정과목 자동 추천
- 담당자 수동 수정
- 수동 수정값 우선 적용
- 수동 수정값 학습 또는 룰 저장
- 분석 결과 저장 후 전표/현금출금결의서 생성 시 동일 데이터 사용

업무상 필요한 주요 계정과목 예시는 다음과 같습니다.

- 소모품비
- 집기비품
- 컴퓨터소프트웨어
- 지급수수료
- 부가세대급금
- 가지급금(업체)

구매 품목 예시 처리 기준은 다음과 같습니다.

- 키보드/마우스/케이블 등 소모성 부품은 소모품비로 분류
- PC 본체, 모니터, 장비 등 자산성 품목은 집기비품 등 자산 계정으로 분류
- 소프트웨어/라이선스는 컴퓨터소프트웨어 등 지정 계정으로 분류
- 동일 품목을 여러 개 구매한 경우 가능한 경우 하나의 품목 행으로 병합
- 전표 적요에는 전체 수량 합산값이 아닌 품목 건수 또는 업무상 필요한 수량 표기를 사용

주의 사항:

- 담당자가 화면에서 `집기비품`을 `소모품비`로 수정하고 저장하면 이후 전표, 현금출금결의서, 재분석 결과에 반영되어야 합니다.
- AI 분석 결과보다 담당자 수동 수정값이 우선되어야 합니다.
- 동일 상품을 여러 개 구매한 경우 불필요하게 여러 줄로 분리되지 않도록 병합 규칙이 필요합니다.

### 5.5 AI 분석 기능

목표 시스템은 구매 세금계산서/견적서 분석 보조 용도로 AI 분석 기능을 포함할 수 있습니다.

ERP 업체는 다음 중 가능한 방식을 제안해 주시기 바랍니다.

- ERP 내부 룰 기반 분석
- OCR/문서 분석 엔진 사용
- 외부 AI API 사용
- AI 미사용, 담당자 확인 중심 방식

AI 기능을 제안할 경우 다음 사항을 견적에 포함해 주시기 바랍니다.

- API 사용료
- 개인정보/거래정보 전송 범위
- 장애 시 fallback 방식
- 분석 결과 검증 방식
- 사용자가 수정한 결과를 우선 적용하는 방식

### 5.6 ERP 전표 생성

ERP 업체는 자동화 대상 데이터를 ERP 전표로 등록할 수 있는 기능을 개발해야 합니다.

필수 기능은 다음과 같습니다.

- 세금계산서 작성일자를 ERP 회계일/전표일자로 반영
- 사업장명은 ERP 사업장 기준으로 반영
- 거래처는 사업자등록번호 우선으로 매칭
- 계정과목은 분석/업무 룰에 따라 반영
- 공급가액, 부가세, 합계금액 정합성 검증
- 차변/대변 합계 일치 검증
- 전표번호 저장
- 전표 PDF 또는 ERP 출력물 저장
- 등록 실패 시 오류 사유 저장
- 중복 전표 등록 방지
- 재시도 가능

구매 전표 기본 구조 예시는 다음과 같습니다.

- 차변: 소모품비/집기비품/컴퓨터소프트웨어 등 품목별 계정
- 차변: 부가세대급금
- 대변: 가지급금(업체) 또는 ERP 기준 지급 계정

정기 전표 기본 구조는 거래처별/비용 성격별 ERP 업무 룰에 따릅니다.

정확한 계정과목, 적요 문구, 부서, 사업장, 거래처 코드는 ERP 업체와 당사 담당자가 별도 확정합니다.

### 5.7 현금출금결의서 생성

전표 또는 청구서 처리 후 현금출금결의서를 자동 생성해야 합니다.

필수 기능은 다음과 같습니다.

- 현금출금결의서 PDF 생성
- 작성일자는 세금계산서 작성일자와 일치
- 사업장명은 법인명이 아닌 실제 사업장명 사용
- 청구부서, 작성자, 지급처, 제목, 근거, 내용, 청구금액, 정산금액 표기
- 구매 품목 요약 표시
- 총액 검증
- 법인/사업장별 양식 또는 푸터 적용
- 생성 실패 시 재생성 가능
- PDF 파일 서버 보관

Zoom의 경우 현금출금결의서는 청구서 표시 금액 그대로 생성해야 하며, ERP 전표 없이도 생성 가능해야 합니다.

### 5.8 문서 세트 관리

업무 건별로 필요한 문서 세트를 관리해야 합니다.

구매 처리 문서 세트:

- ERP 전표 PDF
- 세금계산서 PDF
- 품의결재본 PDF
- 현금출금결의서 PDF
- 필요 시 견적서 PDF

정기 처리 문서 세트:

## 11. 검수 기준

다음 시나리오를 기준으로 검수합니다.

### 11.1 구매 처리 검수

- 컴퓨존 세금계산서가 수신되면 구매 처리 목록에 표시됩니다.
- 세금계산서 PDF가 저장됩니다.
- 견적서가 주문번호 기준으로 연결됩니다.
- 품목 분석 결과가 표시됩니다.
- 같은 품목/단가의 반복 구매 건은 병합됩니다.
- 담당자가 계정과목을 수정하면 저장 후 전표와 현금출금결의서에 반영됩니다.
- 사업장은 실제 사업장명으로 표시됩니다.
- ERP 전표 작성일자는 세금계산서 작성일자와 일치합니다.
- 현금출금결의서 작성일자도 세금계산서 작성일자와 일치합니다.
- 전표 PDF, 세금계산서, 품의결재본, 현금출금결의서가 문서 세트로 준비됩니다.

### 11.2 정기 처리 검수

- 정기 거래처 세금계산서가 수신되면 정기 처리 목록에 표시됩니다.
- 거래처별 수신 예정일/누락 상태가 정확히 계산됩니다.
- ERP 전표가 생성됩니다.
- 현금출금결의서가 생성됩니다.
- 문서 세트가 지정 프린터로 출력됩니다.
- 처리 완료 상태와 담당자/처리 시간이 저장됩니다.

### 11.3 Zoom 처리 검수

- Zoom 청구서 PDF가 수신/저장됩니다.
- ERP 전표와 품의결재본은 생성하지 않습니다.
- 청구서와 현금출금결의서만 문서 세트로 구성됩니다.
- 금액은 환율 계산 없이 표시 금액 그대로 기재됩니다.
- 자동 출력 및 수동 재출력이 가능합니다.

### 11.4 누락 모니터링 검수

- 정기 거래처별 수신 예정/누락 상태가 표시됩니다.
- 누락 거래처에 안내 메일이 발송됩니다.
- 내부 확인용 참조 메일이 포함됩니다.
- 발송 이력이 남습니다.
- 중복 발송이 방지됩니다.
