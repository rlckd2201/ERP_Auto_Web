# 구매 처리 공용 PC

운영 서버의 `web_v1/backend/.env`에 다음을 설정하면 신규 계정을 포함해 모든 로그인 사용자의 구매 ERP 입력·현금출금결의서 생성을 243 PC에서 실행합니다.

```dotenv
PURCHASE_SHARED_AGENT_IP=172.17.30.243
PURCHASE_SHARED_AGENT_ID=DESKTOP-55LQ6BN-TEST
PURCHASE_SHARED_USER_IDS=*
```

- 원클릭·구매 ERP 직접 입력·현출 재생성에 동일하게 적용합니다.
- 작성자와 처리자는 요청한 사용자로 기록하고, 출력은 그 사용자의 PC와 선택한 프린터로 보냅니다.
- 243의 연결·필수 환경이 정상이 아니면 요청을 보류합니다. 다른 사용자 PC로 자동 전환하지 않습니다.
- 같은 243 Agent에서 구매·자동 정기 작업을 순서대로 실행합니다. 기존 전표 재입력 방지와 저장된 문서만 출력하는 경로를 유지합니다.
- `*`는 전체 로그인 사용자를 뜻합니다. 빈 값은 기존 로컬 실행, 쉼표·세미콜론·공백으로 구분한 계정 목록은 지정 사용자만 공용 실행합니다. 계정 이름 일부에 붙인 `*`는 패턴으로 처리하지 않습니다.
- 정기 자동 처리는 기존 `REGULAR_AUTO_AGENT_IP` 설정을 사용합니다. 이 구매 정책은 정기 수동 처리 경로를 변경하지 않습니다.

배포 시 원본 모듈·`.env`·DB를 백업하고 실행 중인 작업을 확인합니다. 코드 변경으로 Agent 번들 해시가 달라지면 기존 자동 업데이트를 거쳐 243의 최신 버전·준비 상태를 다시 확인합니다. 검증을 위해 실제 전표나 출력을 중복 실행하지 않습니다.

회계 서버 감시 스크립트의 `S-RecoverStoppedListener`는 접속 포트가 없을 때만, 기록된 실행 파일·명령·PID·생성 시각이 모두 일치하는 잔존 프로세스를 종료합니다. 여러 후보나 다른 포트 점유자, 기록 불일치는 복구하지 않습니다. 구현은 `tools/accounting_listener_recovery.ps1`, 모의 검증은 `tools/test_accounting_listener_recovery.ps1`입니다.

운영 `C:\ERP_DB\run_accounting_backend.ps1`에는 이 함수를 포함하고, `S-Run`의 포트가 없는 분기에서 `S-RecoverStoppedListener`를 호출합니다. 감시 작업의 `HealthUrl`은 실제로 HTTP 200을 반환하는 `https://127.0.0.1:8081/api/version`을 사용합니다. 현재 포털 인증 구조에서 `/health`는 HTTP 403을 반환하므로 생존 확인 주소로 사용할 수 없습니다. 감시 작업을 수정할 때도 기존 작업 XML을 먼저 백업합니다.
